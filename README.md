# AI 工具机会发现 Skill

从一个人的真实工作出发，梳理重复任务与困难，判断是否值得做工具，再决定 AI 是否适合参与。

**[阅读 Skill 规则](SKILL.md)** · [查看项目记录模板](assets/project-dossier-template.md)

## 适合什么时候用

你有机会了解朋友或同事的实际工作，想从访谈、观察或现有材料中找到值得验证的问题。也可以带着已有访谈记录、原型反馈或未完成的工具想法继续推进。

## 从调研到实现

| 阶段 | 主要产出 |
| --- | --- |
| 了解真实工作 | 最近一次任务的触发条件、具体步骤、工具与协作方式 |
| 整理机会 | 工作流、直接证据、假设和仍需核实的问题 |
| 判断是否值得做 | 继续调研、调整现有流程、开发常规工具或采用 AI 的建议 |
| 验证与实现 | 可检验的假设、最小原型、评价方式和失败记录 |
| 整理项目案例 | 从问题到决策、实现与迭代的作品集材料 |

流程允许得出“不开发”或“不使用 AI”的结论。一次访谈中的抱怨、好评或使用意愿，不能直接当成需求已经验证。

## 开始使用

在支持 Skill 的 Agent 中加载本目录，入口是 `SKILL.md`。保留 `references/` 和 `assets/`，其中包含各阶段使用的参考规则与记录模板。

下面是一段启动提问示例。

> 我想了解一位朋友工作中反复发生的任务，判断是否有值得做成工具的机会。请先帮我选定一个具体流程，一次只问我一个主要问题，不要急着给产品方案。

已有材料时，可以直接说明材料来自哪里、记录了哪一次任务，以及希望继续判断什么。

## 文件导航

- [`references/`](references/) 提供访谈、机会判断、验证与作品集整理方法。

## 使用边界

这是用于引导研究与开发的工作方法，不是经过验证的市场机会清单。使用时需要区分观察、受访者陈述与推断，不编造访谈、结果或技术可行性；工作资料应先获得授权并做必要脱敏。
